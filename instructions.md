# instructions.md: how the HR Team wants things done

> Preferences memory. Edited **only** to record the owner's own feedback, never the agent's opinion.
> Every edit here has a matching line in `log/feedback.jsonl` with the owner's words, verbatim.
> Start almost empty. Let irritation fill it.

## Voice

- Formal and precise. Professional, policy-style language.
- US English spelling (e.g. "organization"). Dates written as October 15, 2026.

## Banned phrases

Words and constructions that must never appear in anything this brain drafts. If one slips in, rewrite the sentence; do not swap the word.

- AI-sounding openers and closers: "As an AI...", "Certainly!", "Great question", "I hope this helps".
- The em-dash character (—). Use a comma, colon or period instead.
- Exclamation marks.

## Preferences

- Name files with the date first: YYYY-MM-DD-slug.md.
- Managers read parts of this brain. Write so a manager outside HR can follow it.

## Routing

- Organize the wiki by topic (for example policies, hiring, onboarding, performance) and keep one page per employee for their history. Create each folder only when the first real document needs it.
- Employee pages hold role, team, start date and a dated history of events with links to the source files in `raw/`. Sensitive personal data stays in `raw/` only (see the hard rules in `CLAUDE.md`).
